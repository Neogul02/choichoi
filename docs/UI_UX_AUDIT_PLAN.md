# UI/UX 점검·개선 계획

> 작성 2026-11-26 · 코드 점검 + 실제 화면 캡처(아이패드 가로 1180·세로 820, 폰 390, 데스크톱 1440) · 대상 전 화면

이 앱을 쓰는 사람은 세 부류다 — **매장 캐셔**(아이패드 POS, 서서 빠르게 누름), **주방**(출근부 키오스크·내 일정), **관리자**(노트북·폰으로 인사·급여·통계). 판단 기준은 "그 사람이 그 자리에서 실수 없이 빨리 끝내는가"다.

## 2. 화면 공통

### 2-1. 창(모달) 동작 규칙 — P0
지금 규칙이 화면마다 다르다. 하나로 정한다.

| 창 종류 | 바깥 클릭 | Esc | 예시 |
|---|---|---|---|
| **입력·수정 창**(저장 버튼이 있음) | 닫지 않음 | 닫기 전, 바꾼 값이 있으면 "저장 안 하고 닫을까요?" 확인 | 급여 상세(공제 입력), 일괄 편집, 파트 관리, 근무 배정, 4대보험 내보내기, 정산표 붙여넣기, 팝업 매출 입력 |
| **보기 전용 창** | 닫음 | 닫음 | 직원 달력, 계약서 목록 |
| **확인 창**(ConfirmDialog) | 닫음 = 취소 | 취소 | 삭제 확인 |

대상(지금 바깥 클릭으로 닫힘): `PayrollDetailModal`, `BulkEditModal`, `ShiftManageModal`, `StaffAssignModal`, `ImportStaffFromPopupModal`, `InsuranceExportModal`, `PopupManualEntryModal`, `SalesSheetPasteModal` → 바깥 클릭 제거. `StaffCalendarModal`, `StaffContractsListModal`, `ConfirmDialog`는 유지.
구현: 공통 `<ModalShell kind="form" | "view">` 하나로 배경·패널·Esc·스크롤 잠금·포커스를 묶고, 각 창은 내용만 그린다(지금은 창마다 같은 마크업을 복사).

### 2-2. 메뉴 이름 정리 — ✅ 완료(11/26)

| 지금 | 바꿀 이름 | 누가 |
|---|---|---|
| 스케줄 (`/schedule`) | **내 근무** | 모든 직원 — 내 달력·예상 급여 |
| 일정표 (`/roster`) | **전체 근무표** | 매니저 이상 — 읽기 전용 |
| 인사 › 스케줄 달력 | **근무 배정** | 관리자 — 편집 |
| 출근부 | 그대로 | 관리자·키오스크 |

한 화면이 한 이름만 쓰게: 버튼·제목·토스트·README까지 같은 단어로 맞춘다.

### 2-3. 글씨 크기 바닥 — P1
- 정보 텍스트 최소 **11px**, 숫자(금액·건수)·버튼 최소 **12px**, POS·키오스크 화면은 최소 **13px**.
- 10px 이하는 보조 설명(※ 안내문)만 허용하고, 경고·오류 문구는 12px 이상.
- 순서: POS(`PosTodaySummary`, 메뉴 카드) → 키오스크(`AttendanceClient`) → 통계 달력 칸 → 근무표 칸(`DayCell` 9px 파트 칩).
- 근무표 칸의 9px 칩은 칸이 좁아서 생긴 것 — 월 보기에서는 이름 대신 "3/4명"만, 이름은 날짜 상세에서 보이게 정보 양을 줄여 글씨를 키운다.

### 2-4. 색·모양 토큰 — P2
- 회색 hover(`#ececeb`), 옅은 배경(`#f5f6f7`, `#f0f0f0`), 본문 회색(`#555`), 테두리(`#e4e4e4`, `#e0e0e0`, `#d8d8d8`) → 기존 토큰(`canvas-soft`, `hairline`, `ink-muted`)으로 치환. 없는 단계는 토큰을 하나 추가한다.
- 모서리: 지금 `rounded-lg` 252 · `rounded-xl` 179 · `rounded-2xl` 53 · `rounded-md` 39가 섞여 있다. **역할로 고정** — 카드·창 `xl`, 버튼·입력 `lg`, 칩·배지 `full`, 표 안 작은 버튼 `md`.

### 2-5. 불러오기·빈 화면·오류 문구 — P2
- "불러오는 중..." / "불러오는 중…" 두 표기가 30곳에 섞여 있다 → `…` 하나로, 큰 영역은 스켈레톤으로 통일.
- 빈 화면은 "없습니다"로 끝내지 말고 다음 행동을 준다 — 예: 팝업 분석 "등록된 팝업이 없습니다" → "설정 › 팝업 관리에서 팝업을 추가하세요" + 이동 버튼.
- `showMsg()`가 문구 끝말("하세요", "앞입니다")로 성공/오류를 추측한다 → `toast.success/ error`를 직접 부르게 바꿔 오분류를 없앤다.

### 2-6. 접근성 — P2
- `outline-none`만 있고 포커스 표시가 없는 입력 13곳 → `focus-visible:ring` 추가(키보드로 쓰는 관리자 노트북).
- 아이콘만 있는 버튼(×, ‹ ›, ▾)은 대부분 `aria-label`이 있음(97곳) — 새 버튼도 같은 규칙.

## 3. 화면별

### POS (`app/pos`)
- **매출 배너가 기본으로 가려져 있다**(`salesHidden` 기본 true) → 손님 앞이라 일부러 가린 것. 유지하되 "가림" 상태를 기기에 기억(지금은 새로고침마다 가려짐).
- **끝난 팝업 경고**(빨간 띠)는 좋다. 다만 결제 버튼 자체는 눌린다 → 경고 상태에서 결제를 누르면 한 번 더 확인.
- **오늘 현황**이 배너·배틀·현황·메모까지 세로로 길다 → 아이패드 가로에서는 메뉴 판 오른쪽 열로 옮겨 스크롤 없이 보이게.
- 메뉴 카드: 이름 `text-sm`, 가격 `text-xl` — 캐셔는 가격보다 이름·단축키를 먼저 찾는다. 이름을 키우고 가격을 한 단계 줄인다.

### 출근부 키오스크 (`app/attendance`)
- 퇴근 창에 휴게 4칸 + 전화번호 키패드 + 확인이 한 화면 — 아이패드 세로에서 세로 스크롤이 생기는지 확인 필요.
- 휴게를 안 고르면 확인이 안 눌리는데, 그 이유가 화면에 안 보인다 → 확인 버튼 위에 "쉬는시간을 골라 주세요" 표시.

### 통계 (`app/(admin)/stats`)
- 리뉴얼 후 구조는 정리됨. 남은 것:
  - 달력 칸은 `만` 단위, 목록은 `₩` 전체 — 같은 숫자를 두 단위로 읽게 된다. 달력 칸 hover/탭 시 전체 금액 표시.
  - 정산 예상이 달력 목록·계산기 버블·팝업 분석 세 곳에서 다른 모양으로 보인다 → 목록 합계를 기준 숫자로 두고, 버블은 "재료비·기타까지 뺀 최종"만 맡게 역할을 나눈다.
  - 팝업 분석이 접힌 상태에서 무엇이 들어있는지 한 줄로만 안내 → 마지막으로 본 팝업 이름을 보여 주면 다시 펼칠 이유가 생긴다.

### 인사 (`app/(admin)/hr`)
- 왼쪽 직원 목록 + 오른쪽 탭(근무 배정 / 급여 정산 / 계약서)이 한 화면 — 폰에서는 왼쪽 목록이 위로 쌓여 탭까지 한참 내려가야 한다 → 폰에서는 탭을 위로, 직원 목록은 접기.
- 급여 정산 표의 지급 체크·공제 일괄 적용 같은 **돈이 움직이는 버튼**과 보기용 버튼이 같은 모양 → 지급·일괄 적용은 채운 버튼 + 확인 창으로 구분.

### 내 근무 / MY (`app/schedule`, `app/my`)
- `MyPageClient` 1,023줄 — 계정·은행·계약서·탈퇴가 한 화면 → 섹션 탭(내 정보 / 계약서 / 계정)으로 나누고, 탈퇴는 맨 아래 별도 영역.

### 설정 (`app/(admin)/settings`)
- 메뉴 행마다 팝업 칩이 붙어 메뉴 20개 × 팝업 4개면 칩 80개 → 위에 "팝업 보기" 선택을 두고 그 팝업 기준 체크박스 열 하나로 바꾸면 한눈에 읽힌다.

### 주문 현황 (`app/orders`)
- 삭제함(11/26) — 화면·전용 서버 액션·proxy 경로·README 스크린샷까지.

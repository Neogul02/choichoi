# 통계 탭 리뉴얼 계획

> 작성 2026-11-23 · 대상 `app/(admin)/stats/**`

## 1. 문제

| 지금 | 결과 |
|---|---|
| 섹션 10개가 한 페이지에 세로로 나열 | 원하는 숫자를 찾으려면 길게 스크롤해야 함 |
| 첫 화면에 서버 조회 8개 동시 실행(오늘 요약·오늘 주문 전체·메뉴 집계·달력·달력 정정·팝업 목록·오늘 팝업별·누적) | 첫 로딩이 무겁고, 안 보는 섹션 데이터까지 매번 받음 |
| 같은 숫자가 여러 곳에 중복 (오늘 매출이 요약 카드·오늘 현황·시간대별·오늘 주문에 각각) | 어느 숫자가 맞는지 헷갈리고 유지보수 비용이 큼 |
| 하루를 보려면 '날짜별 상세'(팝업·날짜 선택), 고치려면 '달력 → 날짜 창 → 팝업 입력창' 세 번 이동 | 보기와 고치기가 서로 다른 곳에 흩어져 있음 |
| 팝업 비교 섹션 | 실제로 쓰지 않음 |

## 2. 목표

1. **한 화면에서 판단:** 첫 화면에 "오늘 얼마 팔았나"와 "이번 달 흐름(달력)"만 보인다.
2. **필요할 때만 로딩:** 팝업 분석·하루 상세·주문 목록·누적은 열거나 스크롤해 닿을 때 받는다.
3. **하루는 한 창에서:** 달력 날짜를 누르면 그날 팝업별 매출·시간대·메뉴·주문을 보고 바로 고친다.
4. **중복 제거:** 같은 데이터는 한 곳에서만 보여 준다.

## 3. 새 화면 구성 (위 → 아래)

```
┌─ ① 오늘 ───────────────────────────────────────────┐
│  오늘 매출 ₩ · 주문 · 객단가 · 판매 수량            │  ← 기존 TodaySummary + TodaySection 통합
│  어제/지난주/지난 팝업(같은 일차) 같은 시각 비교     │
│  팝업별 시간대 누적 곡선(팝업 칩으로 전체/개별)      │
│  [메뉴 순위 ▾]  [오늘 주문 목록 ▾]   ← 접힘, 열 때 로딩 │
└────────────────────────────────────────────────────┘
┌─ ② 달력 (월) ─────────────────────────────────────┐
│  기존 달력 + 팝업 띠 + 월 합계/팝업별 합계          │
│  날짜 클릭 → ④ 하루 상세 창                         │
│  [정산 추정 ▾] (수수료·재료비 입력, 접힘)           │
└────────────────────────────────────────────────────┘
┌─ ③ 팝업 분석 (접힘, 팝업 선택 시 로딩) ────────────┐
│  팝업 선택 → 총매출·주문·객단가·운영일 평균 타일    │
│  일별 추이 / 요일별 / 시간대 / 메뉴 비중 차트       │
│  [정산표 붙여넣기] [PDF 보고서]                     │
└────────────────────────────────────────────────────┘
┌─ 누적 총매출 (맨 아래, 화면에 닿으면 로딩) ─────────┐
└────────────────────────────────────────────────────┘

④ 하루 상세 창 (달력 날짜 클릭)
   헤더: 11월 21일 (토) · 그날 합계
   팝업 탭: [대구 #3] [청량리 #2] [날짜 전체]
     · 매출·주문 수 — 정정값/POS값 나란히, 바로 수정·되돌리기
     · 시간대별 매출 / 메뉴별 판매 (POS + 수기)
     · 주문 목록(접힘)
   [저장]
```

데스크톱(lg)에서는 ①과 ②를 좌우 2열로 두어 스크롤 없이 한 화면에 본다.

## 4. 섹션별 처리

| 기존 | 처리 |
|---|---|
| TodaySummary (오늘 매출 카드) | ①로 통합 |
| TodaySection (오늘 현황 곡선·비교) | ①로 통합 + 지난 팝업 같은 일차 비교 추가(POS와 같은 훅) |
| LifetimeTotalCard (누적 총매출) | **맨 아래**, IntersectionObserver로 보일 때 조회 |
| PopupComparisonSection (팝업 비교) | **삭제** (usePopupComparison 포함) |
| PopupStatsSection (팝업별 분석) | ③ 접힘 섹션으로 이동, 펼치기 전엔 조회 안 함 |
| PopupDaySection (날짜별 상세) | **삭제** → ④ 하루 상세 창으로 흡수 |
| MenuBreakdownSection (메뉴 기간별) | ① '메뉴 순위'(오늘)로 축소, 주·월 기간 메뉴는 ③ 팝업 분석의 메뉴 비중으로 대체 |
| HourlySalesSection (시간대별) | **삭제** — 오늘은 ① 곡선, 팝업 기간은 ③ 시간대 분포와 중복 |
| TodayOrdersSection (오늘 주문 목록) | ① 접힘 '오늘 주문 목록', 펼칠 때 조회 |
| CalendarSection | ② 유지, 정산 추정은 접힘으로 |
| DayDetailModal + PopupManualEntryModal | ④ 하루 상세 창 하나로 통합 (팝업별 탭) |
| SalesSheetPasteModal / PopupReportModal | ③에서 그대로 사용 |

## 5. 데이터 로딩

| 언제 | 조회 | 비고 |
|---|---|---|
| 첫 화면(서버) | 오늘 요약, 오늘 팝업별 시간대, 이번 달 달력(+정정), 팝업 목록 | 8개 → **4개** |
| ① 메뉴 순위 펼침 | 오늘 메뉴 집계 | |
| ① 주문 목록 펼침 | 오늘 주문(품목 포함, 1000건 나눠 읽기) | 가장 무거운 조회가 기본에서 빠짐 |
| ② 날짜 클릭 | 그날 팝업별 상세(get_popup_day_sales + 시간대·메뉴), 주문은 탭 펼칠 때 | |
| ③ 펼침 + 팝업 선택 | 팝업 일별·메뉴·시간대·주문 | 기존 usePopupStats 그대로, 시작 시점만 늦춤 |
| 누적 카드가 화면에 닿음 | get_lifetime_sales_totals | |

모두 react-query 캐시로 묶어 접었다 펴도 다시 받지 않는다(staleTime 1~5분). 실시간 구독(orders INSERT)은 ①만 갱신한다.

## 6. 작업 순서 (커밋 단위)

1. **정리:** 팝업 비교·시간대별·날짜별 상세 섹션 삭제, 누적 카드 맨 아래 + 지연 로딩. 서버 프리페치 8→4.
2. **① 오늘 통합:** TodaySummary+TodaySection 합치기, 메뉴 순위·주문 목록 접힘(펼칠 때 로딩), 지난 팝업 비교.
3. **④ 하루 상세 창:** DayDetailModal + PopupManualEntryModal + PopupDaySection 내용을 팝업 탭 하나로. 기존 저장 액션(savePopupDailySales·saveManualDailyMenuSales·날짜 전체 정정) 재사용.
4. **② 달력·③ 팝업 분석 정리:** 정산 추정 접기, 팝업 분석 접힘·선택 시 로딩, lg 2열 배치.
5. 검증: 타입·린트·테스트, dev 프리뷰에서 실제 데이터(대구 #3, 청량리 #2)로 화면 확인 후 main.

## 7. 완료 기준

- 첫 화면 서버 조회 4개 이하, 팝업 분석·주문 목록·누적은 열기 전 네트워크 요청 없음.
- 달력 날짜 하나를 눌러 그날 팝업별 매출을 보고, 정정·메뉴 수량 입력·되돌리기까지 창을 벗어나지 않고 끝낸다.
- 오늘 매출 숫자가 화면에 한 곳에만 있다.
- 삭제한 섹션의 기능 중 여전히 필요한 것(정산표 붙여넣기, PDF 보고서, 수기 입력, 주문 삭제)이 모두 새 위치에서 된다.

## 8. 위험·주의

- **정정 우선순위:** 팝업 정정 > (그날 팝업이 하나면) 날짜 전체 정정 > POS — DB 함수 `get_popup_day_sales`가 정한다. 하루 상세 창도 이 함수 값만 보여 주고 클라이언트에서 다시 계산하지 않는다.
- **주문 삭제:** 지금 '오늘 주문 목록'에 있는 삭제 기능은 ①과 ④ 주문 탭 양쪽에 둔다.
- **모바일:** ④ 창은 아래에서 올라오는 시트(최대 90vh), 탭은 가로 스크롤.
- 삭제 파일: PopupComparisonSection, usePopupComparison, PopupDaySection, HourlySalesSection, (통합 후) TodaySummary·DayDetailModal·PopupManualEntryModal은 새 컴포넌트로 대체.

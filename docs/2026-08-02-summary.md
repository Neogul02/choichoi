## 2. 안정성 — 오류 수집 & 복원력

- **프로덕션 오류 수집**: 서버 액션 실패와 클라이언트 에러 바운더리를 기존 Discord 웹훅으로 자동 수집. 같은 오류는 5분에 1건만 전송(도배 방지). 공용 `ErrorScreen` 컴포넌트로 5개 error.tsx 통일 — 오류 코드(digest) 표시, 오프라인 상태 구분
- **POS 결제 재시도 UX**: 결제 실패 toast에 "다시 시도" 버튼 추가(10초 유지), 오프라인/네트워크 오류 구분 문구
- **백그라운드 복귀 시 자동 갱신**: 폰을 껐다 켜면 낡은 데이터가 남던 문제 — 1분 이상 백그라운드 후 복귀하거나 네트워크가 회복되면 전체 데이터 재조회

## 3. 성능 — 서버 액션 레이턴시

- **Discord 웹훅 지연 제거**: 로그인·주문 삭제·메뉴 CRUD·직원 관리·계약 서명 등 8곳에서 웹훅 전송을 기다리다 응답하던 것을 `next/server`의 `after()`로 응답 후 비동기 전송하도록 변경. 특히 로그인은 서버 액션 직렬화 때문에 후속 요청까지 지연시키고 있었음
- **결제 응답 병렬화**: 주문 생성 시 매출 집계와 재고 차감을 순차 → 병렬 실행으로 DB 왕복 1회 절감

## 4. DB 정규화 & 인덱스 진단

- **핫패스 복합 인덱스**: `orders(popup_id, created_at)`, `roster_assignments(staff_role, popup_id, work_date)` — EXPLAIN으로 실제 채택 확인
- **중복·미사용 인덱스 정리**: 4건 삭제, FK 커버링 인덱스로 대체(인덱스 총량 순증 0)
- **드리프트 집계 컬럼 정리**: `user_profiles.total_revenue`(주문 합산 중복 저장)를 실시간 계산으로 단일화
- **로스터 정합성 FK**: `roster_assignments → roster_shifts` 복합 FK 추가로 비정규화 복사본(`staff_role`·`popup_id`)의 정합성을 DB가 강제하도록 보강. 단일 FK는 유지(주방 배정의 cascade 보장용)
- 상세 진단·유지 판정 근거: `docs/2026-08-02-db-normalization-index-audit.md`

## 사고 2건 (당일 발생·즉시 복구)

### 사고 1 — 스키마 축소 순서 실수

`total_revenue` 컬럼을 코드 배포 전에 DB에서 먼저 삭제해, 아직 그 컬럼을 참조하던 프로덕션 코드(직원 계정연결 목록, `/my` 프로필)가 일시적으로 실패. 사용자 제보로 발견 → 컬럼 즉시 복원 + 주문 데이터로 백필해 복구.

**교훈**: 컬럼·테이블 삭제는 반드시 "코드 참조 제거 → 배포 확인 → DB 삭제" 순서(expand/contract)를 지킬 것.

### 사고 2 — 복합 FK가 깨뜨린 PostgREST 조인

로스터 정합성 FK 추가로 `roster_assignments → roster_shifts` 사이 관계가 2개가 되면서, Supabase REST 계층이 어느 관계로 조인할지 판단하지 못해 근로계약서 작성 화면의 "배정된 근무 스케줄"과 급여 상세 조회가 조용히 빈 값을 반환. 사용자가 "계약서 쓸 때 스케줄이 안 뜬다"로 제보 → 원인 파악 후 즉시 관계를 명시하는 힌트 문법으로 수정.

**교훈**: 같은 두 테이블 사이에 FK를 추가할 때는 그 테이블 쌍을 조인하는 모든 쿼리를 먼저 확인할 것.
